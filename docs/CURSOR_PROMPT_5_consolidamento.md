D. Every day is computed — no "non calcolato" in the customer view
----
Today the date picker only reads `daily_kpi`; if the job never ran for that day, or ran before prompt 3 added a metric, cards render "non calcolato per questo giorno". That is not acceptable for the customer. Rules:
1. **Compute on demand.** `GET /api/reporting/daily-kpi?venueId=&day=` checks completeness against `REQUIRED_KPI_IDS` (a single exported list in `backend/reporting/kpiCatalog.ts`, covering prompts 1–3: the four hero kpis, `minutes_per_customer_by_dept_area/_counter`, `choice_index_by_dept`, `department_area_m2`, `queue_*`, `counter_wait_*`, adjacency, flow field, promo spots, behaviour modes, occupancy, `recon_*`, checks). The UI shows one page-level state — "Sto preparando il 12 settembre… circa 4 minuti" with a progress bar — and polls every 10 s; no card is rendered half-empty. If the parquet does not exist for that day, the day is disabled in the picker with the tooltip "Nessun dato per questo giorno".
2. **Backfill.** `npm run kpi:backfill -- --venue <id> --from 2026-09-01 --to today` computes every missing kpi for every day with a parquet, skipping kpis already present (per kpi, not per day). Run it once as part of this prompt for Treviglio and commit the log to `backend/reporting/backfill-2026-09-17.log`.
3. **Occupancy.** `occupancy_people_in_store` currently returns `48 / not_computed: 1-minute occupancy needs parquet`. Implement it in the daily job from the parquet: distinct customer ids present in each 1-minute bin of opening hours (same customer pool as `entrances`, staff strips excluded), store mean, p95 and max per slot and per day. Remove the `not_computed` status from the codebase entirely; a kpi is `ok`, `unreliable` (with reason) or `no_coverage`.
